# AI Tutor 开发计划

## 1. 开发目标

AI Tutor 采用分阶段开发方式，先完成可运行的 MVP，再逐步扩展 AI 教学、RAG 知识库、个性化推荐和 Agent 能力。

整体建设路径：

```text
AI 助手 MVP → AI 教师 → RAG 增强 → 个性化学习 → AI Agent
```

## 2. 阶段一：AI 学习助手 MVP

### 2.1 阶段目标

实现学生可以注册登录、维护学习档案，并与 AI 老师进行基础学习问答。

### 2.2 开发内容

用户系统：

- 注册。
- 登录。
- 当前用户信息查询。
- Token 认证。

学习档案：

- 创建学习档案。
- 查询学习档案。
- 修改学习档案。

AI 聊天：

- 创建会话。
- 发送问题。
- 调用大模型。
- 返回 AI 回答。
- 保存聊天记录。
- 查询历史会话。

### 2.3 验收标准

- 用户可以完成注册和登录。
- 用户可以维护学习方向、目标、水平和偏好。
- 用户可以向 AI 提问并获得回答。
- 聊天记录可以保存和查看。
- AI 回答可以结合学习档案生成更个性化内容。

### 2.4 建议开发顺序

```text
数据库初始化
  ↓
用户注册登录
  ↓
学习档案接口
  ↓
AI 模型调用封装
  ↓
聊天接口
  ↓
聊天页面
  ↓
历史会话页面
```

## 3. 阶段二：AI 教学模式

### 3.1 阶段目标

让 AI 从“回答问题”升级为“引导学习”。

### 3.2 开发内容

知识点管理：

- 知识点新增。
- 知识点修改。
- 知识点删除。
- 知识点树查询。

教学模式：

- 选择知识点开始教学。
- AI 生成知识讲解。
- AI 生成理解检查问题。
- 学生提交回答。
- AI 评价反馈。
- 更新学习记录。

AI 出题：

- 根据知识点生成题目。
- 保存题目。
- 学生答题。
- 生成答案解析。

### 3.3 验收标准

- 管理员可以维护知识点。
- 学生可以进入知识点教学模式。
- AI 可以完成讲解、提问、评价流程。
- AI 可以生成结构化练习题。
- 学习记录可以更新。

## 4. 阶段三：RAG 知识库增强

### 4.1 阶段目标

支持用户上传资料，让 AI 基于资料内容回答问题。

### 4.2 开发内容

文档管理：

- 上传 PDF、Markdown、TXT。
- 保存文档信息。
- 查询文档列表。
- 展示文档处理状态。

RAG 处理：

- 引入 LangChain4j。
- 文档解析。
- 文本切片。
- Embedding 向量生成。
- 向量数据库存储。
- 根据问题检索相关片段。
- 基于检索内容生成回答。

### 4.3 验收标准

- 用户可以上传学习资料。
- 系统可以解析文档并完成向量化。
- 用户可以基于资料提问。
- AI 回答可以结合资料内容。
- 资料不足时系统可以明确提示。

## 5. 阶段四：个性化学习系统

### 5.1 阶段目标

系统根据学习数据分析学生情况，并生成个性化推荐。

### 5.2 开发内容

学习分析：

- 统计已学知识点。
- 统计答题正确率。
- 分析错题知识点。
- 计算掌握程度。
- 识别薄弱知识点。

个性推荐：

- 生成复习建议。
- 生成学习计划。
- 推荐练习题。
- 推荐下一步学习知识点。

### 5.3 验收标准

- 系统可以展示学习概览。
- 系统可以识别薄弱知识点。
- 系统可以生成学习建议。
- 系统可以生成周学习计划。

## 6. 阶段五：AI Agent 学习助手

### 6.1 阶段目标

让系统从被动回答升级为主动辅助学习。

### 6.2 开发内容

Agent 能力：

- 学习规划 Agent。
- 教学 Agent。
- 出题 Agent。
- 分析 Agent。

Agent 流程：

- 分析学习目标。
- 制定学习路径。
- 生成学习任务。
- 跟踪任务完成情况。
- 根据学习结果调整计划。

### 6.3 验收标准

- Agent 可以根据学生目标生成学习计划。
- Agent 可以根据学习记录调整路线。
- Agent 建议结果可解释。
- 关键操作需要用户确认。

## 7. 前端开发计划

### 7.1 页面清单

MVP 阶段页面：

- 登录页。
- 注册页。
- 首页。
- 学习档案页。
- AI 聊天页。
- 历史会话页。

扩展阶段页面：

- 知识点学习页。
- 题目练习页。
- 文档上传页。
- 学习分析页。
- 学习计划页。
- 管理员后台页。

### 7.2 前端重点

- 聊天页面体验要简洁。
- AI 回答支持 Markdown 展示。
- 长回答支持加载状态。
- 文件上传展示处理进度。
- 学习数据尽量可视化。

## 8. 后端开发计划

### 8.1 模块清单

后端模块包括：

- 用户认证模块。
- 学习档案模块。
- 会话与聊天模块。
- AI 服务模块。
- 知识点模块。
- 题目模块。
- 学习记录模块。
- 文档与 RAG 模块。
- 学习分析模块。

### 8.2 后端重点

- 密码加密存储。
- 接口权限校验。
- AI 调用统一封装。
- 聊天上下文裁剪。
- AI 输出格式校验。
- 文件上传安全控制。
- 异步处理文档解析和向量化。

## 9. 测试计划

### 9.1 功能测试

需要测试：

- 注册登录流程。
- 学习档案保存。
- AI 聊天问答。
- 聊天记录查询。
- 教学模式流程。
- AI 出题和答题反馈。
- 文档上传和 RAG 问答。
- 学习分析和计划生成。

### 9.2 接口测试

重点测试：

- 参数为空。
- Token 失效。
- 无权限访问。
- 非本人数据访问。
- AI 调用失败。
- 文件格式不支持。

### 9.3 AI 效果测试

需要测试：

- 回答是否适合学生水平。
- 回答是否结构清晰。
- 出题是否符合知识点。
- 答案解析是否正确。
- RAG 回答是否基于资料。
- 资料不足时是否拒绝编造。

## 10. 里程碑计划

| 阶段 | 目标 | 结果 |
|---|---|---|
| 第 1 阶段 | AI 助手 MVP | 可注册、登录、聊天、保存记录 |
| 第 2 阶段 | AI 教师 | 可教学、出题、记录学习进度 |
| 第 3 阶段 | RAG 知识库 | 可上传资料并基于资料问答 |
| 第 4 阶段 | 个性化学习 | 可分析薄弱知识点并生成计划 |
| 第 5 阶段 | AI Agent | 可主动规划和辅助学习 |

## 11. 开发注意事项

- 优先保证 MVP 可运行，不要一开始做过多复杂功能。
- AI 调用部分必须封装，避免业务代码直接依赖具体模型。
- 密码不能明文存储。
- 文件上传必须限制格式和大小。
- RAG 文档处理建议异步执行。
- AI 生成题目必须做格式校验。
- 学习分析早期可以先用规则，后期再引入更复杂算法。

## 12. 推荐实施策略

建议先完成以下闭环：

```text
注册登录 → 学习档案 → AI 问答 → 聊天记录
```

完成 MVP 后，再扩展：

```text
知识点 → 教学模式 → 出题 → 学习记录
```

最后加入：

```text
RAG 知识库 → 学习分析 → 个性化推荐 → Agent
```
