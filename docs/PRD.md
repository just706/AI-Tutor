# 产品范围与验收

## 定位

AI Tutor 当前是面向计算机学习者的个性化学习助手。下一版以正在学习 Java 的初学者为首个验证人群，优先使用集合框架教材验证完整学习过程，再扩展到 Python、计算机网络等主题。这是迭代范围，不代表系统已限制其他用户注册。

核心价值不是功能数量，而是让学习者完成一条可追踪的循环：

```text
选择知识点 → 诊断理解 → 讲解 → 理解检查 → 练习 → 反馈与复习
```

## 当前用户能力

学生用户可以注册、维护学习档案、创建会话、使用普通 AI 问答或 RAG 问答、开始教学、生成和提交练习、查看学习分析、管理学习记忆、上传个人资料并生成个人图谱。管理员接口可以维护知识点。

前端当前入口包括聊天、学习、知识图谱、练习、资料库、分析、Agent 建议和个人资料。系统没有独立的管理端页面。

## 当前范围与边界

| 能力 | 当前状态 | 验收口径 |
| --- | --- | --- |
| 普通问答 | 已实现 | 会话归属校验、保存问答和 AI 调用日志 |
| 个性化教师 | 已实现基础编排 | 记忆、知识图谱上下文、规则策略和学习会话被记录；策略尚未反馈给同一次模型回答 |
| 练习 | 已实现 | 客观题确定性评分，主观题模型评分并保存记录 |
| 学习计划 | 已实现规则版本 | 根据学习分析和周/月周期生成，不是模型规划器 |
| RAG | 已实现关键词基线 | 仅使用当前用户已完成文档；找不到证据时返回不足证据 |
| 个人图谱 | 已实现异步候选与发布 | 上传后可触发提取，用户显式发布才替换图谱 |
| Agent 建议 | 已实现规则流程 | 生成、确认、完成、驳回和事件记录，不会自主执行写入动作 |
| Python/LangGraph/向量库/SSE | 未实现 | 只在方案文档中作为候选，不纳入当前验收 |

## 关键产品问题

当前项目已经具备学习工具链，但还没有证明学习效果优于直接使用通用模型。后续迭代应优先验证：资料引用是否正确、练习是否与薄弱点相关、状态是否有证据、用户是否能完成学习循环。建议先建立一套计算机学习资料测试集，再决定是否引入向量检索或多 Agent。

## 建议的首版主线

首页优先突出继续上次学习、上传教材、查看需要复习的知识点。聊天、知识库、路径和图谱继续保留，但应服务于学习主线。当前实现仍可从多入口进入，以上属于下一阶段产品收敛建议。

首版交付需要同时满足：同一教材会话可连续问答并查看引用；至少两个 Java 知识点可走通诊断、讲解、检查、练习与反馈；学习状态及复习建议能追溯到证据。功能验收与学习效果评测分别记录，不能因流程可用就宣称已证明教学效果。

实施顺序、阶段状态、任务清单和具体验收统一见 [Development 的总体路线](Development.md#总体路线与当前进度)。本文件只维护产品范围，不重复维护阶段进度。向量检索、Python、LangGraph 和 Multi-Agent 属于按评测结果选择的候选方案，不是首版交付前提。

## 验收原则

1. 任何学习状态都能追溯到答题、教学评价、学习记录或用户明确反馈。
2. 文档问答显示来源；没有足够来源时明确说明，不把流畅文本当作证据。
3. AI 失败时不丢失用户问题，且前端能够重试或回到普通问答。
4. 同一用户不能读取或修改其他用户的会话、文档、记忆和个人图谱。
5. “掌握度”在当前版本只是 0–100 的工程指标；在完成证据模型前，不应把它宣传为精确测量。
