# AI Tutor 系统架构设计

## 1. 架构目标

AI Tutor 系统采用前后端分离架构，目标是实现可扩展、可维护、可替换模型的智能学习助手平台。

架构设计目标：

- 支持学生端和管理员端功能扩展。
- 支持 GPT、Qwen、DeepSeek 等不同大模型接入。
- 支持 RAG 知识库增强问答。
- 支持学习记录、答题记录和个性化分析。
- 支持后期 AI Agent 能力扩展。

## 2. 总体架构

```text
                  学生 / 管理员
                        |
                    Vue3 前端
                        |
                 Spring Boot 后端
                        |
 ------------------------------------------------
| 用户中心 | 学习中心 | AI 中心 | 题目系统 | 数据分析 |
 ------------------------------------------------
          |                         |
        MySQL                  AI 服务层
                                  |
                    -------------------------------
                   |                               |
             大模型接口                     RAG 知识库
        GPT / Qwen / DeepSeek       LangChain4j + 向量数据库
```

## 3. 技术架构

### 3.1 前端层

前端采用 Vue3 技术栈。

主要职责：

- 用户登录注册页面。
- 学习档案维护页面。
- AI 聊天页面。
- 教学模式页面。
- 题目练习页面。
- 学习分析页面。
- 文档上传页面。
- 管理员后台页面。

推荐技术：

- Vue3。
- Vue Router。
- Pinia。
- Axios。
- Element Plus。
- Markdown 渲染组件。

### 3.2 后端层

后端采用 Spring Boot。

主要职责：

- 用户认证和权限控制。
- 学习档案管理。
- 聊天会话管理。
- AI 服务调用封装。
- 知识点和题目管理。
- 学习记录和答题记录管理。
- 文档上传和 RAG 流程调度。
- 学习分析和推荐生成。

推荐技术：

- Spring Boot。
- Spring Security 或 JWT。
- MyBatis-Plus 或 JPA。
- MySQL。
- Redis。
- LangChain4j。

### 3.3 数据层

结构化数据存储在 MySQL 中。

主要数据：

- 用户信息。
- 学习档案。
- 聊天记录。
- 知识点。
- 题目。
- 答题记录。
- 学习记录。
- 文档元数据。
- 学习计划。

### 3.4 AI 服务层

AI 服务层负责统一封装大模型调用。

主要职责：

- 模型供应商适配。
- Prompt 模板管理。
- 上下文裁剪。
- 流式输出处理。
- 输出格式约束。
- 调用失败重试。
- AI 调用日志记录。

### 3.5 RAG 知识库层

RAG 知识库用于支持基于上传资料的增强问答。

组成部分：

- 文档存储。
- 文本解析。
- 文本切片。
- Embedding 模型。
- 向量数据库。
- LangChain4j 编排。
- 检索增强 Prompt。

## 5. 核心业务流程

### 5.1 AI 聊天流程

```text
用户输入问题
  ↓
前端发送聊天请求
  ↓
后端校验登录状态
  ↓
读取学习档案和历史上下文
  ↓
AI 服务层构造 Prompt
  ↓
调用大模型接口
  ↓
返回回答给前端
  ↓
保存用户消息和 AI 消息
```

### 5.2 教学模式流程

```text
用户选择知识点
  ↓
系统读取学习档案和知识点信息
  ↓
AI 生成讲解内容
  ↓
AI 生成理解检查问题
  ↓
用户回答
  ↓
AI 评价回答
  ↓
系统更新学习记录
```

### 5.3 AI 出题流程

```text
用户选择知识点和难度
  ↓
后端构造出题 Prompt
  ↓
AI 生成结构化题目
  ↓
后端校验题目格式
  ↓
保存题目
  ↓
返回给前端展示
```

### 5.4 RAG 问答流程

```text
用户上传资料
  ↓
系统保存文件
  ↓
LangChain4j 加载并解析文档
  ↓
文本切片
  ↓
生成 Embedding
  ↓
保存到向量数据库
  ↓
用户基于资料提问
  ↓
检索相关片段
  ↓
组合资料和问题
  ↓
调用大模型生成回答
```

## 6. 数据流设计

### 6.1 用户数据流

- 前端提交注册或登录信息。
- 后端完成校验并生成访问令牌。
- 前端保存令牌并在后续请求中携带。
- 后端根据令牌识别用户身份。

### 6.2 学习数据流

- 学生学习行为写入学习记录。
- 答题结果写入答题记录。
- 聊天内容写入对话记录。
- 分析模块定期或实时更新掌握程度。

### 6.3 AI 数据流

- 后端收集用户问题、学习档案和上下文。
- AI 服务层调用模型。
- 结果返回前端并保存。
- 关键 AI 结果可用于后续学习分析。

## 7. 安全架构

安全设计包括：

- 使用 JWT 或 Session 实现登录认证。
- 密码使用安全哈希算法存储。
- 用户数据按用户 ID 隔离。
- 管理员接口进行角色权限校验。
- 文件上传限制类型、大小和路径。
- 大模型请求中避免携带无关敏感信息。

## 8. 可扩展设计

### 8.1 模型可替换

AI 模型调用通过统一接口封装，支持后期切换：

- GPT。
- Qwen。
- DeepSeek。
- 本地大模型。

### 8.2 向量数据库可替换

RAG 存储层保留抽象接口，支持后期切换：

- Milvus。
- pgvector。
- Elasticsearch Vector。
- Qdrant。

### 8.3 多学科扩展

知识点表通过 `subject` 和 `parent_id` 支持树形结构，可扩展到：

- Java。
- Python。
- 数学。
- 英语。
- 计算机基础。

## 9. 部署架构

开发环境可以采用单机部署：

```text
Vue3 前端
Spring Boot 后端
MySQL
Redis
向量数据库
```

生产环境建议拆分部署：

```text
Nginx
  ↓
前端静态资源
  ↓
后端 API 服务
  ↓
MySQL / Redis / 向量数据库
  ↓
第三方大模型服务
```

## 10. 架构风险

### 10.1 大模型响应不稳定

解决方案：

- 增加超时控制。
- 增加失败重试。
- 支持备用模型。
- 保存错误日志。

### 10.2 RAG 检索不准确

解决方案：

- 优化文本切片策略。
- 调整检索 TopK。
- 使用更合适的 Embedding 模型。
- 增加来源引用和资料不足提示。

### 10.3 数据增长导致性能下降

解决方案：

- 关键字段增加索引。
- 聊天记录分页查询。
- 文件解析异步处理。
- 历史上下文裁剪。
