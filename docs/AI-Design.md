# AI Tutor AI 模块设计

## 1. 模块目标

AI 模块是 AI Tutor 的核心能力层，负责实现智能答疑、教学引导、自动出题、答题评价、学习分析、RAG 知识库问答和后期 Agent 能力。

设计目标：

- 统一封装大模型调用。
- 支持多模型供应商切换。
- 支持基于学生档案的个性化回答。
- 支持教学流程而不是简单问答。
- 支持基于资料的 RAG 增强问答。
- 支持结构化输出，便于系统保存和分析。

## 2. AI 模块架构

```text
                 业务服务层
                     |
                 AI 服务层
                     |
 ------------------------------------------------
| Prompt 管理 | 模型适配 | 上下文管理 | RAG 编排 | 输出解析 |
 ------------------------------------------------
          |                         |
      大模型接口               LangChain4j
 GPT / Qwen / DeepSeek              |
                              向量数据库
```

## 3. 模型接入设计

### 3.1 模型供应商

系统可支持以下模型：

- GPT。
- Qwen。
- DeepSeek。
- 本地大模型，后期扩展。

### 3.2 统一模型接口

后端应封装统一 AI 调用接口，业务模块不直接依赖具体模型供应商。

接口能力包括：

- 普通文本生成。
- 流式文本生成。
- JSON 格式输出。
- Embedding 向量生成。
- 调用日志记录。
- 超时和失败处理。

### 3.3 模型调用参数

建议支持配置：

- `provider`：模型供应商。
- `modelName`：模型名称。
- `temperature`：回答随机性。
- `maxTokens`：最大输出长度。
- `timeout`：超时时间。
- `stream`：是否流式输出。

## 4. Prompt 设计原则

### 4.1 基础原则

Prompt 应遵循：

- 明确 AI 角色。
- 明确学生背景。
- 明确输出格式。
- 明确回答边界。
- 鼓励逐步讲解。
- 避免编造无依据内容。

### 4.2 AI 老师角色 Prompt

示例：

```text
你是一个耐心的 AI 学习老师。
学生的学习方向是：{learningDirection}
学生的学习目标是：{learningGoal}
学生当前水平是：{currentLevel}
学生偏好的学习方式是：{learningPreference}

请用适合该学生水平的方式回答问题。
回答时尽量包含：
1. 概念解释
2. 简单示例
3. 使用场景
4. 常见错误
5. 下一步学习建议
```

## 5. AI 聊天设计

### 5.1 输入信息

AI 聊天需要组合以下信息：

- 用户当前问题。
- 学生学习档案。
- 当前会话上下文。
- 必要的系统 Prompt。

### 5.2 上下文策略

为了避免上下文过长，建议：

- 只携带最近若干轮对话。
- 对较长历史对话进行摘要。
- 优先保留与当前问题相关的内容。
- 控制最大 Token 数。

### 5.3 输出要求

普通学习问答建议输出：

- 简短结论。
- 详细解释。
- 示例说明。
- 易错点。
- 学习建议。

### 5.4 MVP 阶段实现

阶段 4 已实现普通非流式聊天：

- 后端通过 `POST /api/ai/chat` 接收用户问题和会话 ID。
- 服务层校验当前用户是否拥有该会话。
- 调用 DeepSeek 前保存用户消息。
- Prompt 会组合学生学习档案和最近会话上下文。
- DeepSeek V4 请求显式使用非思考模式，避免 MVP 阶段处理 `reasoning_content`。
- DeepSeek 调用成功后保存 AI 回复。
- DeepSeek 调用失败时返回 `code: 600`，并写入 `ai_call_log`。

## 6. AI 教学模式设计

### 6.1 教学目标

AI 教学模式的目标是让 AI 从“回答问题”升级为“引导学习”。

### 6.2 教学流程

```text
知识讲解
  ↓
理解检查
  ↓
生成练习问题
  ↓
学生回答
  ↓
AI 评价反馈
  ↓
推荐下一步学习内容
```

### 6.3 教学 Prompt 示例

```text
你是一个 Java 教学老师。
当前知识点是：{knowledgePointName}
学生当前水平是：{currentLevel}

请按照以下结构教学：
1. 用通俗语言解释知识点
2. 给出一个简单示例
3. 提出一个理解检查问题
4. 给出学习提醒

注意：不要一次性讲太多内容，适合基础学生循序渐进学习。
```

### 6.4 学生回答评价 Prompt

```text
请根据学生对问题的回答进行评价。

知识点：{knowledgePointName}
问题：{question}
学生回答：{studentAnswer}

请输出：
1. 是否基本正确
2. 得分，0-100
3. 学生回答中的优点
4. 存在的问题
5. 补充讲解
6. 下一步建议
```

### 6.5 阶段 6 落地接口

当前阶段先实现教学闭环，不进入题库阶段。

- `POST /api/teaching/start`：选择知识点后创建教学会话，AI 输出讲解和理解检查问题。
- `POST /api/teaching/evaluate`：学生提交理解检查回答，AI 输出评价、得分和建议。
- `GET /api/teaching/records`：查询当前学生的知识点学习状态和掌握程度。

AI 评价结果会要求包含 `得分：0-100`，后端据此更新 `learning_record.mastery_level`。

## 7. AI 出题设计

### 7.1 出题输入

生成题目时需要输入：

- 知识点。
- 学生当前水平。
- 题目类型。
- 难度。
- 题目数量。

### 7.2 题目输出格式

建议要求 AI 输出 JSON，便于后端解析。

```json
{
  "questions": [
    {
      "questionType": "single_choice",
      "content": "题目内容",
      "options": ["A", "B", "C", "D"],
      "answer": "A",
      "analysis": "答案解析",
      "difficulty": "medium",
      "knowledgePoint": "Java 接口"
    }
  ]
}
```

### 7.3 出题约束

AI 出题需要满足：

- 题目必须与知识点相关。
- 题干表达清晰。
- 客观题必须有明确答案。
- 答案解析应说明原因。
- 难度应符合学生当前水平。

## 8. 答题评价设计

### 8.1 客观题评价

单选题、判断题等客观题可由后端直接判断。

评价内容：

- 是否正确。
- 正确答案。
- 答案解析。
- 关联知识点。

### 8.2 主观题评价

简答题、开放题可由 AI 评价。

评价输出：

- 得分。
- 正确点。
- 不足点。
- 修改建议。
- 推荐复习知识点。

### 8.3 阶段 7 落地接口

当前阶段实现题目生成和答题反馈闭环。

- `POST /api/questions/generate`：AI 按知识点、题型、难度生成结构化题目。
- `GET /api/questions`：查询已生成题目。
- `GET /api/questions/{questionId}`：查询单个题目。
- `POST /api/questions/{questionId}/answer`：提交答案并保存答题记录。

落地规则：

- AI 出题必须输出 JSON，后端会校验 `questions` 数组、题型、难度、选项、答案和解析。
- 客观题 `single_choice`、`true_false` 由后端判分，避免重复调用 AI。
- 主观题 `short_answer` 由 AI 批改，反馈中必须包含 `得分：0-100`。
- 答题后更新 `learning_record.mastery_level`，供后续学习分析阶段使用。

## 9. RAG 模块设计

### 9.1 RAG 目标

RAG 用于解决通用大模型不了解学生个人教材、课程资料和学习笔记的问题。

### 9.2 技术选型

由于系统后端采用 Spring Boot，推荐使用 LangChain4j 作为 RAG 编排框架。

LangChain4j 负责：

- 文档加载。
- 文本解析。
- 文本切片。
- Embedding 生成。
- 向量检索。
- Prompt 组装。
- 大模型调用。

向量数据库可选：

- Milvus。
- pgvector。
- Elasticsearch Vector。
- Qdrant。

### 9.3 文档处理流程

```text
用户上传文件
  ↓
保存文件基础信息
  ↓
LangChain4j 加载文档
  ↓
解析文本
  ↓
文本切片
  ↓
生成 Embedding
  ↓
写入向量数据库
  ↓
更新文档处理状态
```

### 9.4 检索问答流程

```text
用户提问
  ↓
问题向量化
  ↓
向量数据库召回相关片段
  ↓
筛选 TopK 片段
  ↓
组装资料上下文
  ↓
调用大模型
  ↓
返回回答和来源
```

### 9.5 RAG 回答约束

RAG 回答应遵循：

- 优先基于检索资料回答。
- 资料不足时明确说明没有找到依据。
- 不应编造资料中不存在的内容。
- 尽量返回引用来源。

### 9.6 阶段 8 落地策略

当前阶段先实现 RAG 后端 MVP，不引入外部向量数据库。

- 上传资料后同步解析 `txt`、`md`、`markdown` 文本。
- 后端按固定长度和重叠窗口切分文本，写入 `document_chunk`。
- 检索阶段先使用 MySQL chunk 加关键词评分召回 TopK。
- 命中资料后将 chunk 组装进 Prompt，再调用大模型回答。
- 未命中资料时直接返回“资料中没有找到足够依据”，避免模型编造。
- `embedding_id` 先保存占位值，后续迁移到 Milvus、pgvector、Qdrant 等向量库。

## 10. 学习分析设计

### 10.1 分析数据

AI 分析可使用：

- 学习档案。
- 聊天记录。
- 学习记录。
- 答题记录。
- 错题记录。
- 知识点掌握度。

### 10.2 分析输出

输出内容包括：

- 当前学习水平。
- 已掌握知识点。
- 薄弱知识点。
- 错误原因。
- 推荐复习内容。
- 学习计划建议。

### 10.3 学习计划 Prompt 示例

```text
请根据学生的学习数据生成一份本周学习计划。

学习目标：{learningGoal}
当前水平：{currentLevel}
薄弱知识点：{weakKnowledgePoints}
最近错题：{wrongQuestions}

请输出：
1. 本周学习目标
2. 每日学习安排
3. 推荐练习内容
4. 复习建议
```

## 11. AI Agent 设计

### 11.1 Agent 目标

Agent 模块用于让系统从被动问答升级为主动学习辅助。

### 11.2 Agent 类型

| Agent | 职责 |
|---|---|
| 学习规划 Agent | 分析目标并制定学习计划 |
| 教学 Agent | 解释知识并检查理解 |
| 出题 Agent | 生成练习并调整难度 |
| 分析 Agent | 分析错题并优化路线 |

### 11.3 Agent 执行原则

- Agent 的建议需要可解释。
- 高影响操作需要用户确认。
- 不自动删除或修改用户重要资料。
- 所有关键执行结果需要记录。

## 12. AI 安全与质量控制

### 12.1 安全控制

- 不向模型发送无关敏感信息。
- 控制用户上传资料访问权限。
- 对用户输入进行基础安全过滤。
- 对模型输出进行格式校验。

### 12.2 质量控制

- 使用固定 Prompt 模板提高稳定性。
- 结构化输出使用 JSON Schema 校验。
- 对模型调用失败设置重试机制。
- 对 RAG 回答返回来源信息。

### 12.3 日志记录

AI 调用建议记录：

- 用户 ID。
- 请求类型。
- 模型供应商。
- 模型名称。
- Token 用量。
- 调用状态。
- 错误信息。
