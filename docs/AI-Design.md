# AI、记忆与检索

## 当前模型调用

普通教师使用 DeepSeek 同步调用。上下文包含服务端预先确定的本轮教学计划、用户档案、当前用户的有效学习记忆和最近最多 10 条消息；单条用户消息上限 4000 字符。AI 调用成功或失败都会设计为可记录，但主教师事务失败时相关记录可能随事务回滚。

系统提示模型回答学习问题，但没有独立事实核验器。结构化功能通过 JSON 约束和解析器处理，解析失败会走业务异常或降级；因此模型输出仍是外部不稳定依赖。

普通教师的共用提示要求先按最近题目核对简短作答，分别评价结果与是否提供理由；不能仅因缺少过程判错，也不能在总结中把未解释的部分归因为已观察到的概念错误。题目不在上下文时先澄清，用户质疑时复核并明确纠正误判。这些规则覆盖全部七种教学策略及无策略聊天，是阶段四个人走查发现问题后的提示修正；本地契约测试只能证明约束及历史被传入模型，不代表模型语义判断已通过真实验收。

2026-10-29八例真实生成的内容审阅为6通过、2未通过，发现同一回复内先错误肯定再改口，以及追问预设未给出的解题路径。后续共用提示要求先独立核算再给一致结论，并开放询问所用方法；该后续版本只完成本地契约检查，预算用完后未追加生成。原始失败及逐例判断见 [反馈复测](../backend/evaluation/stage4-feedback-results.md)，不将旧版内容结果用于验收新提示。

## 教学编排

自由问答的意图由规则识别为 `chat`、`learn`、`practice`、`path`、`analysis` 或概念困难。教学策略为 `concept_first`、`example_first`、`source_code_first`、`prerequisite_first`、`practice_first`、`debug_misconception`、`summary_review` 等规则结果。策略、步骤和导航动作会被保存；强制的诊断、检查及练习流程由显式开启的循序学习提供。

普通教师先校验所属会话和学习会话，再根据意图、最近步骤与知识地图选择策略。固定系统指令与本轮 JSON 上下文进入同一次模型调用；生成成功后保存并返回同一策略。主题来自提问或已有学习会话，不要求加入 Java 概念名单；知识地图未收录的主题仍可选择教学方式，但不能据此虚构前置关系。模型失败仍遵循原有事务回滚，尚未接入教材问答的失败恢复协议。

| 策略 | 本次生成约束 |
| --- | --- |
| `concept_first` | 核心概念、必要例子、理解检查 |
| `example_first` | 先举例，再提炼概念并检查理解 |
| `source_code_first` | 先解释可确认的源码流程；缺少源码时说明限制，不编造版本实现 |
| `prerequisite_first` | 先补知识地图提示的前置项，再回到当前问题；无前置项时先确认基础 |
| `practice_first` | 先给一道练习及作答要求，等待回答，不提前公布答案 |
| `debug_misconception` | 用具体问题或对比例子定位困难，不直接宣布已掌握 |
| `summary_review` | 总结要点、确认理解缺口、给出复习建议 |

主题、档案、记忆和前置项名称按数据解释，知识地图及掌握度仅是教学提示。以上是模型指令，不能保证每次回答都遵守，也不是事实核验或教育效果证明。2026-09-29 的自编数学问题已检查七种策略、连续困难反馈和未收录主题；模型对未定义的“星云投影”自行选择了天文学解释，术语歧义澄清仍需改进。教材问答的证据约束与这一普通教师流程保持独立。

## 学习会话与掌握度

循序学习通过显式入口开启。普通会话先补充所属领域及参考片段；教材会话从用户选定的教材中按完整短主题检索，不仅根据名称猜测含义。有依据后模型一次生成短讲解、补讲和五道选择题，Java 验证结构后保存；诊断作答进入讲解，点击检查后才出检查题，检查正确进入练习，练习正确给本轮反馈。答错展示该题解析、补讲并改用另一检查题；题库用尽停在复习。模糊回答、口头“懂了”、过期提交不能推进。模型负责备课，不直接更新流程状态或掌握度。

首版只支持选项判定。备课依据为本轮手动资料或选定教材的检索片段；教材流程复用现有 RAG 检索器，不根据历史助手回答备课。片段及文件名标记合计超过 4000 字符时要求收窄主题或减少教材，不静默截断依据。选中教材列表和备课引用冻结，逐步保存到回答历史，可刷新查看；引用表示整轮上下文，尚非逐句或逐题核验。无片段或模型认为资料不足时终止开始，不切换无依据回答。

讲解、补讲与题目均要求受资料支持：新例子只变更资料明确给出规则的输入，不从单个示例推广未给出的一般规则；这些提示约束仍不能替代事实核验。新备课使用 schema 4：服务端把原资料保留原字、原顺序地编号，模型一次返回五题统一列表、顶层 `distinctions` 目录，以及每个错误选项的 `distinctionId,explanation,evidenceIds`，不返回引文文本。每条反馈可引用 1–4 段，覆盖推导涉及的多条规则；Java 根据编号还原完整原文、解析区分标签并保存到内部题库，同时检查诊断／检查／练习的标签覆盖。五题的位置由 Java 分配。

Java 拒绝不存在、重复或空的证据编号、不完整的错误选项映射、未知或未使用的区分标签、阶段覆盖不足、模型额外抄写的引文、非法 JSON、重复字段和尾随内容，不尝试修复原响应。选项仅靠空白差异重复也会被拒绝。原文按中文句末标点和空行分段，不按英文句点切割；最多64段，剩余原文完整保留。编号存在和原文未被改写，只能证明引用可追溯，不能证明所选证据相关、解释成立、选项只有一个正确答案或题干没有暗示答案。schema 4 的真实内容验收仍需按开发记录单独审阅。

新备课校验通过后，由 Java 一次性重排选项，将答案键和各错误选项的补讲、原文依据同步映射。同一轮中选项数相同且可重排的题目，各答案位置的数量差最多为一；顺序随机，不固定为 A、B、C 循环。题干、讲解和原文内容不改写，排好的题库随进度保存，刷新和再次作答不重排，旧题库维持原序。检测到独立字母 A–D、常见中英文位置引用（如“选项A”“以上皆是”）时，对应题目保留原序；核心讲解或通用补讲存在此类引用时整轮保留。检测是保守规则，可能把变量名当作引用，也不能识别所有自然语言依赖，仍需内容审阅。分布约束只覆盖可重排的同组题目，不保证实际走过的题目子集均衡，也不代表题目具有诊断区分度。

新备课还要求每题写全本题计算或推演所需的操作序列、输入、函数和已知条件，概念定义仍可依据本轮资料。`TutorQuestionContext` 在选项重排前检查题干、选项、解析及错误反馈中的常见跨题引用，如“上一题”“第1题的答案”“previous question”；同时拦截题干以“上述序列”“the above function”等缺少本题前提的表达开头。题号前缀允许保留；本题先写条件、再用“上述”指代本题条件可以通过。该检查是有限语言规则，会漏掉其他表达，也可能误拦把这些词语当作讨论对象的题目，不能证明条件充分或语义独立。

命中时整轮新备课返回600，不补造条件、不拼接前题答案、不自动追加模型调用；失败进度与历史保持原状，用户可重新发起备课。模型原文证据不作为生成指令检查，旧题库的读取和作答不重新套用此校验。新提示下真实生成的题目质量需单独验收；旧响应回放只能证明规则拦截及兼容行为，不能证明模型已学会独立出题。

作答后展示本次选择及该题参考选项。诊断错误先展示对应说明及原文，再进入核心讲解；检查或练习错误时，用所选选项的说明补讲，再进入不同检查题；题目耗尽仍给对应说明并停在复习。未选择的反馈与未来答案不公开，不增加作答时的模型调用。这里只说明所选选项的问题，不据此断定学生的真实错因或能力。旧备课缺少反馈时继续使用原通用补讲；已有单引文反馈的快照继续按原字段显示，不重新生成。

schema 4 新学习先按模型给出的区分标签关联：从未作答题中寻找与最近一次错误反馈标签相同的题，再按原文重合数排序；同分或没有同标签候选时保持原序。此前只按证据关联的快照继续比较反馈原文并集，按完全相同的编号和文本计算去重交集；没有历史错误时直接按原序。答对检查后进入练习仍可参考此前最近一次错误，后续错误会替代更早的错误依据。选题说明随当前题目展示并进入聊天历史，内部保存依据和共同证据编号。没有选题策略的旧快照沿用旧顺序，刷新不重新排序。

此规则不依赖 Java 或其他学科名称，不增加模型调用；只在已有两道检查、两道练习中选择，不生成额外题目。多个题可能引用相同宽泛片段，候选题反馈并集也可能涵盖多个概念，因此原文重合不证明题目测量同一知识点或适合学生的真实错因。资料引用关联与教学效果仍需分别验收。

2026-10-20 真实内容审阅发现，相同模型标签也可能对应不同的实际差异。页面对标签命中与未命中改用中性选题说明，不再据此声称测量同一区分点；内部选题规则和已保存进度不变。离线审查脚本为每题唯一答案、错误反馈、证据支持及实际选题路由收集明确判决，绑定原始录制指纹；未审项保持待定，不能汇总为通过。它不自动判断语义，也未接入在线备课准入。当前代码的原样回放、真实生成内容审阅及教学效果需分别验证，具体命令见 [开发记录](Development.md)。

阶段、题库与作答证据保存在服务端，结束会话和本轮通过均不能视为长期掌握。尚未实现根据自由文本解释实时诊断、实时生成新题或经过验证的错因选题。固定手动资料题集与验收结果见 [开发记录](Development.md#阶段-2形成教学闭环)，教材检索备课需另行验收真实内容。

教师会创建或复用学习会话，状态包括 `CREATED`、`DIAGNOSING`、`PLANNING`、`TEACHING`、`PRACTICE`、`REFLECTION`、`COMPLETED`。意图可以直接改变状态，关闭接口会标记完成。

持久化练习与教学评价通过 `LearningEvidenceService` 保存题目／上下文快照、作答、完整反馈、原始分数、判分方式、时间、状态前后值、前次有效评分 ID、更新规则及原响应。客观题仅按保存的答案键判0或100分；模型题库答案不因此得到事实认证。临时 AI 练习与循序学习仍不写入掌握度，后者的内容准入尚未通过。

`recent-evidence-v1` 的首条有效评分建立新基线，不沿用无法核实的旧历史最高分。此后 `new = round(0.4 × max(0, old − penalty) + 0.6 × observation)`，其中 `penalty = min(30, 5 × floor(距前次有效评分的完整天数 / 7))`；仅新有效评分触发调整。模型的 observation 及 new 均上限84，原始模型分数完整保留。状态阈值仍为85／60以兼容既有页面及策略；这些权重、上限和阈值是未校准的工程规则，不是教育测量。历史数据不回填证据，查看页面不会降低分数。

针对性复习由用户在分析页生成：每个知识点仅使用最新有效评分，状态低于85或该次得分低于60时创建任务；未评分证据不用于选题。持久化练习复用评估时保存的题目和答案快照，教学评价使用固定的核心概念、例子及适用边界回述题，并保留原教学上下文供模型评价。它们是已有资料的针对性再检查，不是新题生成或独立的内容核验。生成不调用模型，不使用未准入的循序学习题库。

同一来源只生成一个任务，每点已有待完成任务时不再创建。首次复习立即到期；最新证据若来自复习，后续任务至少间隔一天且后端拒绝提前计分。任务 ID 是独立去重范围，因此不会与原题的相同答案相互抑制。一个任务只接收一次有效评分：低分也表示完成本次尝试，后续可再生成间隔任务；未评分尝试保留证据及原响应、保持任务待完成，相同回答重放，修改回答后可再次提交；模型失败不写成功证据。完成、状态更新和结果保存同一事务提交。用户仍能查看来源及结果证据；完成任务只表示做过一次检查，不表示已掌握。模型评价的可靠性限制与状态上限仍适用。

模型反馈须恰有一行明确的“得分：整数”或 `Score: integer`，范围0–100；缺失、多处得分、越界或包含明确资料／证据不足、无法评价等措辞时保存 `score=null`、不改变状态及估算时长，不再默认60分。未评分答题保留空正确性，排除正确率和平均分的分母，也不据此判为薄弱点。规则只能拒绝有限格式和措辞，不能判断所有语义冲突。模型调用失败不写成功答题或证据，失败日志仍按既有机制保存。

同用户、同题、等价客观答案或相同文本答案去重；教学评价按会话、知识点、相同回答去重。教学开始时保存知识点绑定，评价先检查会话归属和绑定，错误知识点或缺少绑定的旧会话不能评分；旧会话需重新开始教学，不依据标题猜测关联。文本仅去首尾空白，客观答案使用原判分的规范化。重放返回原响应中当时的状态值；当前状态通过分析接口读取。重复提交不额外计分、计时或调用模型，复习任务使用独立任务ID区分后续尝试。

分析页将待复习与已完成分别分页；已完成按完成时间和ID倒序，全部历史可访问。完成后展示最新保存结果；翻页失败保留上一页，允许重试。完整分页接口与仍限100条的兼容预览列表区分，见 [API](API.md#针对性复习)。

## 学习记忆

系统支持 `preference`、`difficulty_pattern` 和 `misconception`。只有检测到明确措辞才写入：偏好初始置信度 80、180 天过期；困难模式 70、30 天；误解 60、30 天。重复观察最多加到 95；用户可停用或删除，读取时会将过期记录标记为 `EXPIRED`。当前没有让模型自由写入记忆，主要由规则观察教师对话。

## RAG 当前基线

可选Python分支已修复关键词查询与过早澄清：明确命名的对象先检索，唯一历史对象继续沿用，真正多义才澄清。内部搜索按完整问题、明确对象和空格词项取候选，允许返回供后续判读的上下文；这比下面Java基线的完整问题准入宽松，不能将候选当作答案证据。执行器提供已查查询及剩余可用动作，跨段指代主张要求引用对象与事实两段，最终原文核验和模型复核继续保留。6题真实修复回归通过，完整范围见[报告](../backend/evaluation/stage5-agent-fix-results.md)。

支持 TXT、Markdown、PDF、DOC、DOCX。文档保存在本地用户目录，解析后按 800 字符切片、120 字符重叠，检索前 4 段（上限 8）。检索按完整英文词和中文相邻双字片段匹配，并统一“下标/索引”“读取/访问”“同一个/相同”等表达；中英文连写时分别提取词项。去除常见问句用语后，使用 BM25 词频、文档频率和长度权重排序。以问号结尾的教材问句不参与词项计分，避免思考题重复问题而排在解释正文之前；展示和保存的引用仍保留原文。`embedding_id` 仍为 `mysql-keyword` 占位标识；没有 embedding、向量库或独立 reranker。

RAG 只读取当前会话明确选择、属于当前用户且处理完成的文档。教材 ID 随会话保存，资料库与主聊天共用问答流程；未选择教材时不能提问，教材删除或不可访问时必须重新选择。结果包括文档 ID、文件名、片段索引和当时的完整片段原文。候选需要达到查询中文词项 40%、英文词项 50% 的覆盖率；某一类词项不存在时不要求该类覆盖率。这是降低弱匹配的工程阈值，不是答案可信度。没有合格片段时直接返回证据不足，不调用模型。即使片段通过阈值，也不能保证它包含完整答案，仍需核对模型回答及引用。

`RagQuestionParser` 从有限问句结构提取对象与所问内容，不维护学科或概念名单。能够明确对象时，候选必须包含完整名称（英文保持单词边界）；“某概念的属性”“某概念在某方面”等问法还会单独检查属性词项的覆盖率，防止长中文名称掩盖所问内容完全缺失。无法解析的直接问题仍走基础关键词检索。

对“英文名称＋空格＋至少两个汉字属性”的标题（如“ArrayList 索引访问”），先保留上述问句解析，再将名称和属性分开检索。此标题分支要求同一句同时包含完整对象名称及属性归一化后的全部双字词项，避免将不同句中其他对象的属性拼接为依据，或将“虚拟机”与“虚拟线程”等共享前缀当作完整属性；句界按句号、问号、叹号、分号和换行划分，属性没有有效词项时拒绝。单字属性保留原完整名称匹配，不放宽名称或普通问句的阈值。插入其他词语的属性改写仍可能无法召回；同句共现也不证明属性与对象的语义关系。

“甲和乙有什么区别”“比较甲和乙”等一般比较支持中文名称与英文名称。优先寻找同一片段包含两个完整名称的候选；有明确比较字样时正常排序，只有通用描述线索时得分乘以 0.5。没有此类候选时，允许从不同片段、不同已选教材各取一方的描述，要求双方名称所在句子含“是、表示、描述、基于”等描述线索，缺少任何一方则拒答。仅罗列名称不能触发这一补充检索，具体属性问题也不套用一般比较例外。该规则不是逐句证据核验。

用问号或分号明确分开的多个问题，最多拆为 4 部分，分别检索并为每部分保留至少一段候选，再轮流补足剩余名额。片段按 ID 去重，返回顺序就是提示词中的引用顺序；任何部分没有候选、超过 4 部分或必要片段无法装入检索上限时拒答，避免只回答其中一问。逗号、连词和复杂长句不自动拆问。

“某概念有什么特点／特征”这种没有具体属性的问法可检索该对象的描述，无需教材出现“特点”二字；“某概念的测量误差有什么特点”等具体属性仍检查属性覆盖率。所有规则共用于各学科，不添加 Java 或其他学科的概念名单。

RAG 引用按模型请求中的证据顺序随对应回答保存，两个页面刷新后均可展开；界面区分本次引用序号与教材中的片段位置。保存的是当时原文，不会用重处理后的新片段替换旧证据。历史读取重查教材归属与处理状态，失效时隐藏文件名和原文并明确提示；旧消息没有快照时不补造引用。提示词要求各结论就近标注片段序号、逐问检查依据，不把思考题当答案，不补造教材未给出的数值或原因；资料中的指令视为数据。数组列出的是检索证据，这些提示词要求不代表模型的每句回答已经通过程序核验。

RAG 已支持有限规则的跨学科连续追问。含“它／它们”“那两种／这两个概念”“前者／后者”“这个概念”等指代时，从当前用户当前会话最近 10 条消息中选取用户问题，按时间顺序重建话题。对象名称来自“什么是某概念”“解释某概念”“某概念的用途”“甲与乙有什么区别”等句型，也支持简单英文介绍句与带空格的英文名称。导数、牛顿第二定律、机会成本或教材自定义概念不需要加入程序名单；它们只出现在测试材料中。单数要求一个对象，复数与前后者要求两个对象；“后者”之后再问“它”可以沿用选出的对象。明确新话题会替换旧话题，无法识别的新话题不会继续借用更早对象。助手回答不参与对象选择。

对象不明、超出上下文窗口、混合新名称和指代等情况会先澄清，返回空引用且不调用模型。明确后重新检索当前教材；历史问题只提供对象名称，历史回答和旧引用不能替代本次教材证据。用户原问题照常保存，回答开头显示明确后的问题，刷新后仍可查看这一理解说明和引用。没有证据时即使已识别对象也拒答。

此规则没有额外模型调用，并非通用语义理解：复杂多分句、未支持的代词、完全省略对象，以及名称中含“的／在／和”等语法词的复杂专名，仍可能被拆错或需要澄清。已补测“后者底层是什么结构”和“后者有什么特点”，但名称识别成功仍不等于内容召回成功。问号过滤、描述线索和词项覆盖率都是有限规则，可能漏掉特殊排版或语义改写。词法修复均无需重新上传或切片；任意跨片段推理仍有局限，应继续用固定测试集量化，再决定是否加入向量检索。

教材问答失败后保留用户问题及请求状态。重试固定首次选定的教材 ID 和已解析的对象，重新校验权限、检索当前片段；会话后来切换教材或话题不会改变这次重试。成功响应丢失时可通过历史和原请求标识恢复；没有证据或指代不明属于正常完成的拒答／澄清，不作为模型失败自动重试。处理中过期后由用户触发恢复，迟到结果不得覆盖后续成功回答。这些规则没有 Java 学科分支。

## 个人图谱

个人图谱从文档片段异步提取候选节点、关系和证据。关系类型为 `prerequisite`、`contains`、`related`，证据索引必须属于当前批次；单条非法关系会跳过，整体 JSON 非法则使任务失败。提取完成后必须显式发布，发布会替换该用户该文档的旧图谱，不影响公共知识点图谱或教师回答。

提取按每批 10 段执行，单个文档最多 100 段，分为节点提取和既有节点间的关系提取。超过 100 段的教材保留解析及问答能力，跳过自动图谱提取；需要图谱时先拆分教材。此限制属于图谱调用预算，不是 RAG 上传上限。

## 评测方向

现有评估模块主要统计策略分布、调用成功率、时延和学习会话数据，不等同于教育效果评测。阶段 1 的 [固定题集](../backend/evaluation/stage1-cases.json) 包含 20 道 Java 教材题及 12 道跨学科补充题，分别检查检索证据、引用支持、拒答、歧义澄清、提示注入和耗时。运行方法、验证结果及真实模型验收状态统一见 [Development](Development.md#阶段-1-固定题集评测)。检索替身通过不能代替真实回答审阅；有限题集通过也不能证明任意语义理解或教学效果。

阶段四首轮使用 [离线试点材料与记录工具](../backend/evaluation/stage4-pilot.md)，分别记录独立测验和人工检查的反馈／引用错误，按独立学习者汇总。题面操作可通过Java17核验，语义审阅和真实采集仍由人完成。报告保留缺测、帮助、超窗和额外学习记录，不用模型评分或工程掌握分代替独立测验，也不会将合成演练记录为真实学习效果。没有新增线上研究数据接口。

## 候选演进

已将 [Python 教材问答 Agent](../agent-service/README.md) 接入原教材问答接口，可配置启用。有限状态机组织拆解、受限工具调用、引用校验和最终模型复核，Java继续负责身份、所有权、完整历史、持久化预占、事务和最终写入，不复制现有教师／备课流程。网页及真实Java／Python进程通过本地模型替身联调；真实模型内容仍未验收。同一模型的最终复核可能重复原错误，结果固定标记 `semantic_acceptance: not_evaluated`，不继承既有教材题集的验收结论。

向量或混合检索仍需取得对照收益后再决定接入；LangGraph 及 Multi-Agent 尚未采用。后续以同一题集比较原型与当前Java链路的证据支持、拒答、时延和成本，并保留已发现的否定、假设、缺数据和错调查失败场景。
