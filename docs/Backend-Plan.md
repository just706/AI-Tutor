# AI Tutor 后端开发计划

## 1. 文档目标

本文档用于指导 AI Tutor 后端 MVP 阶段开发，重点明确后端技术选型、工程结构、认证规则、公共规范、开发顺序和验收标准。

后端 MVP 的目标不是一次性完成所有 AI Tutor 功能，而是先跑通最核心闭环：

```text
用户注册登录 → 学习档案 → 会话管理 → AI 问答 → 对话记录
```

## 2. 后端 MVP 技术选型

| 类型 | 选型 |
|---|---|
| 后端框架 | Spring Boot |
| ORM 框架 | MyBatis-Plus |
| 数据库 | MySQL |
| 登录认证 | JWT |
| 密码加密 | BCrypt |
| AI 模型 | DeepSeek |
| API 风格 | RESTful JSON API |
| RAG 框架 | LangChain4j，后续阶段引入 |
| 缓存 | Redis，MVP 可暂不强依赖 |

说明：

- MVP 阶段优先保证后端主流程可运行。
- RAG、Agent、复杂学习分析暂不开发，只在代码结构和文档中保留后续扩展方向。
- DeepSeek API Key 不允许硬编码，应通过配置文件或环境变量注入。

## 4. 包职责说明

| 包名 | 职责 |
|---|---|
| `common` | 通用响应、常量、工具类 |
| `config` | Spring 配置、跨域配置、MyBatis-Plus 配置 |
| `controller` | 接收前端请求，返回统一响应 |
| `service` | 业务接口定义 |
| `service.impl` | 业务实现 |
| `mapper` | MyBatis-Plus 数据访问接口 |
| `entity` | 数据库实体类 |
| `dto` | 请求参数对象 |
| `vo` | 响应视图对象 |
| `security` | JWT、登录拦截、用户上下文 |
| `ai` | DeepSeek 调用、Prompt 构造、AI 响应处理 |
| `exception` | 业务异常、全局异常处理 |

开发原则：

- Controller 不直接写复杂业务逻辑。
- Service 负责业务规则和事务控制。
- Mapper 只负责数据库访问。
- Entity 对应数据库表。
- DTO 用于接收请求参数。
- VO 用于返回前端数据。

## 5. 统一响应格式

所有接口统一返回 JSON。

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

建议定义：

```text
Result<T>
```

字段说明：

| 字段 | 说明 |
|---|---|
| `code` | 业务状态码 |
| `message` | 提示信息 |
| `data` | 返回数据 |

常用状态码：

| code | 说明 |
|---|---|
| 200 | 成功 |
| 400 | 参数错误 |
| 401 | 未登录或 Token 无效 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 500 | 系统异常 |
| 600 | AI 服务调用失败 |

## 6. 全局异常处理规则

后端应提供统一异常处理，避免直接向前端暴露堆栈信息。

建议异常类型：

| 异常 | 说明 |
|---|---|
| `BusinessException` | 业务异常 |
| `UnauthorizedException` | 未登录或认证失败 |
| `ForbiddenException` | 权限不足 |
| `AiServiceException` | AI 服务调用失败 |

处理要求：

- 参数错误返回 `400`。
- 未登录返回 `401`。
- 无权限返回 `403`。
- AI 调用失败返回 `600`。
- 未预期异常返回 `500`，日志记录详细错误。

## 7. JWT 认证规则

### 7.1 登录流程

```text
用户提交用户名和密码
  ↓
后端校验账号是否存在
  ↓
校验 BCrypt 密码
  ↓
检查用户状态是否正常
  ↓
生成 JWT Token
  ↓
返回 Token 和用户基础信息
```

### 7.2 Token 携带方式

前端请求受保护接口时，在请求头中携带：

```text
Authorization: Bearer <token>
```

### 7.3 免登录接口

MVP 阶段免登录接口：

```text
POST /api/auth/register
POST /api/auth/login
```

其余接口默认需要登录。

### 7.4 用户上下文

后端应通过 Token 获取当前用户 ID。

涉及用户数据的接口，必须使用当前登录用户 ID 进行数据隔离，不允许前端直接指定其他用户 ID 操作数据。

## 8. 密码安全规则

密码处理必须遵守：

- 不保存明文密码。
- 注册时使用 BCrypt 加密密码。
- 登录时使用 BCrypt 校验密码。
- 接口响应中永远不返回密码字段。
- 日志中不打印用户密码。

数据库字段使用：

```text
password_hash
```

## 10. MVP 接口开发范围

MVP 阶段优先实现以下接口。

### 10.1 用户认证接口

```text
POST /api/auth/register
POST /api/auth/login
GET  /api/users/me
```

要求：

- 注册时校验用户名唯一。
- 登录成功返回 Token。
- 当前用户接口根据 Token 返回用户信息。

### 10.2 学习档案接口

```text
GET /api/profile
PUT /api/profile
```

要求：

- 用户只能查看和修改自己的学习档案。
- 如果首次保存档案，则创建记录。
- 如果已有档案，则更新记录。

### 10.3 会话接口

```text
POST /api/conversations
GET  /api/conversations
GET  /api/conversations/{conversationId}/messages
```

要求：

- 会话必须归属于当前用户。
- 查询消息时必须校验会话归属。
- 会话列表按更新时间倒序返回。

### 10.4 AI 聊天接口

```text
POST /api/ai/chat
```

要求：

- 接收用户问题和会话 ID。
- 校验会话是否属于当前用户。
- 保存用户消息。
- 读取学生档案和最近对话上下文。
- 调用 DeepSeek。
- 保存 AI 回复。
- 返回 AI 回复内容。

MVP 阶段可暂不实现流式输出。

## 11. DeepSeek 接入规范

### 11.1 配置项

建议配置：

```yaml
ai:
  deepseek:
    api-key: ${DEEPSEEK_API_KEY:}
    base-url: ${DEEPSEEK_BASE_URL:https://api.deepseek.com}
    model-name: ${DEEPSEEK_MODEL_NAME:deepseek-v4-flash}
    timeout-ms: ${DEEPSEEK_TIMEOUT_MS:60000}
    max-context-messages: ${AI_MAX_CONTEXT_MESSAGES:10}
```

### 11.2 AI 服务层职责

`ai` 包负责：

- 构造请求参数。
- 组装系统 Prompt。
- 调用 DeepSeek API。
- 解析模型响应。
- 处理调用失败。
- 记录 AI 调用日志。

### 11.3 Prompt 组装规则

AI 聊天 Prompt 应包含：

- AI 老师角色设定。
- 学生学习方向。
- 学生学习目标。
- 学生当前水平。
- 学生学习偏好。
- 最近若干轮对话。
- 用户当前问题。

示例结构：

```text
你是一个耐心的 AI 学习老师。
学生学习方向：{learningDirection}
学生学习目标：{learningGoal}
学生当前水平：{currentLevel}
学生学习偏好：{learningPreference}

请用适合该学生水平的方式回答问题。
回答尽量包含：概念解释、示例、常见错误和学习建议。

历史上下文：
{recentMessages}

学生问题：
{message}
```

### 11.4 AI 调用失败处理

DeepSeek 调用失败时：

- 不应导致系统崩溃。
- 应返回友好错误提示。
- 应记录失败日志。
- 用户消息可以保留。
- AI 回复保存可根据实际情况跳过或保存失败提示。

## 12. RAG 后置策略

MVP 阶段暂不实现 RAG。

后续阶段再引入：

- LangChain4j。
- 文档上传。
- 文本解析。
- 文本切片。
- Embedding 生成。
- 向量数据库。
- 基于资料的问答。

MVP 阶段不建议提前创建复杂 RAG 代码，只在文档和架构中保留扩展方向。

如需要预留，最多保留 `ai` 包的抽象边界，不实现实际 RAG 流程。

## 13. 后端阶段开发路线

后端开发按阶段推进，优先完成 MVP 闭环，再扩展教学、出题、RAG、学习分析和 Agent 能力。

阶段路线如下：

```text
阶段 0：后端项目初始化
阶段 1：用户认证模块
阶段 2：学习档案模块
阶段 3：会话与聊天记录模块
阶段 4：DeepSeek AI 聊天模块
阶段 5：MVP 联调与测试
阶段 6：知识点与教学模式
阶段 7：AI 出题与答题反馈
阶段 8：RAG 知识库
阶段 9：学习分析与推荐
阶段 10：Agent 扩展
```

### 13.1 阶段 0：后端项目初始化

开发目标：完成 Spring Boot 后端基础工程，保证项目可以启动，并具备后续模块开发所需的基础结构。

主要任务：

- 初始化 Spring Boot 项目。
- 配置 Maven 依赖。
- 配置 MySQL 数据源。
- 集成 MyBatis-Plus。
- 创建基础包结构。
- 创建统一响应结构。
- 创建全局异常处理框架。
- 配置跨域访问。

完成标准：

- 后端服务可以正常启动。
- 数据库连接正常。
- 基础健康检查或测试接口可访问。
- 统一响应和异常处理可以正常返回。

### 13.2 阶段 1：用户认证模块

开发目标：实现用户注册、登录和 JWT 认证，为后续所有用户数据接口提供身份基础。

主要任务：

- 创建 `user` 表对应实体和 Mapper。
- 实现用户注册接口。
- 使用 BCrypt 加密密码。
- 实现用户登录接口。
- 登录成功后生成 JWT Token。
- 实现 Token 校验拦截。
- 实现当前用户信息接口。

完成标准：

- 用户可以正常注册。
- 重复用户名无法注册。
- 用户可以正常登录并获得 Token。
- 密码不会明文保存。
- 未登录用户无法访问受保护接口。

### 13.3 阶段 2：学习档案模块

开发目标：实现学生学习档案管理，让 AI 问答能够使用学生背景信息。

主要任务：

- 创建 `student_profile` 表对应实体和 Mapper。
- 实现查询当前用户学习档案接口。
- 实现创建或更新学习档案接口。
- 在服务层保证学习档案按当前用户隔离。

完成标准：

- 用户可以保存学习方向、学习目标、当前水平和学习偏好。
- 用户只能查看和修改自己的学习档案。
- AI 聊天模块可以读取学习档案作为 Prompt 上下文。

### 13.4 阶段 3：会话与聊天记录模块

开发目标：实现 AI 聊天所需的会话管理和消息持久化能力。

主要任务：

- 创建 `conversation` 表对应实体和 Mapper。
- 创建 `chat_history` 表对应实体和 Mapper。
- 实现创建会话接口。
- 实现查询当前用户会话列表接口。
- 实现查询指定会话消息接口。
- 校验会话归属，防止访问他人会话。

完成标准：

- 用户可以创建新的聊天会话。
- 用户可以查看自己的会话列表。
- 用户可以查看指定会话下的历史消息。
- 用户无法读取不属于自己的会话和消息。

### 13.5 阶段 4：DeepSeek AI 聊天模块

开发目标：接入 DeepSeek，实现基础 AI 老师问答能力，并保存完整对话记录。

主要任务：

- 创建 DeepSeek 配置项。
- 封装 AI 服务调用类。
- 构造 AI 老师 Prompt。
- 读取学生档案和最近上下文。
- 实现 AI 聊天接口。
- 保存用户消息和 AI 回复。
- 记录 AI 调用成功或失败日志。

完成标准：

- 用户可以在指定会话中向 AI 提问。
- 系统可以调用 DeepSeek 并返回回答。
- AI 回答能结合学生档案进行表达。
- 用户消息和 AI 回复可以保存到数据库。
- AI 调用失败时返回友好错误，不导致系统崩溃。

### 13.6 阶段 5：MVP 联调与测试

开发目标：完成后端 MVP 闭环测试，确保核心流程稳定可用。

主要任务：

- 测试注册、登录、Token 认证。
- 测试学习档案新增、查询、更新。
- 测试会话创建和历史消息查询。
- 测试 AI 聊天完整流程。
- 补充必要接口测试。
- 同步修正文档与实际实现差异。

完成标准：

- MVP 核心接口均可正常调用。
- 常见异常场景有明确响应。
- 用户数据隔离正常。
- `API.md`、`Database.md`、`AI-Design.md` 与实际实现保持一致。

### 13.7 阶段 6：知识点与教学模式

开发目标：在 MVP 基础上增加知识点体系和 AI 教学流程。

主要任务：

- 实现 `knowledge_point` 表和基础接口。
- 支持知识点树形查询。
- 实现选择知识点开始教学。
- AI 生成知识讲解和理解检查问题。
- 学生提交回答后由 AI 评价。
- 更新学习状态和掌握程度。

完成标准：

- 管理员可以维护知识点。
- 学生可以按知识点进入教学模式。
- AI 可以完成讲解、提问、评价和建议流程。

### 13.8 阶段 7：AI 出题与答题反馈

开发目标：实现 AI 根据知识点生成练习题，并根据学生答题结果提供反馈。

主要任务：

- 实现 `question` 表和题目接口。
- 实现 AI 生成结构化题目。
- 校验 AI 生成题目的格式。
- 实现学生提交答案接口。
- 客观题由后端判分。
- 主观题由 AI 给出评价建议。
- 保存答题记录。

完成标准：

- AI 可以按知识点和难度生成题目。
- 题目包含答案和解析。
- 学生答题后可以获得反馈。
- 答题记录可用于后续学习分析。

### 13.9 阶段 8：RAG 知识库

开发目标：引入 LangChain4j 和向量数据库，让 AI 可以基于用户上传资料回答问题。

主要任务：

- 实现文档上传和文档列表接口。
- 保存文档元数据。
- 引入 LangChain4j。
- 实现文本解析和切片。
- 调用 Embedding 模型生成向量。
- 接入向量数据库。
- 实现基于资料的问答接口。
- 返回回答来源信息。

完成标准：

- 用户可以上传学习资料。
- 系统可以完成文档解析和向量化。
- 用户可以基于资料提问。
- AI 回答优先基于检索资料。
- 资料不足时系统明确提示，不编造依据。

### 13.10 阶段 9：学习分析与推荐

开发目标：基于学习记录、聊天记录和答题记录，生成学习分析和个性化建议。

主要任务：

- 汇总用户学习记录。
- 统计答题正确率。
- 分析薄弱知识点。
- 生成学习概览接口。
- 生成学习建议。
- 生成阶段性学习计划。

完成标准：

- 用户可以查看学习概览。
- 系统可以识别薄弱知识点。
- 系统可以生成可执行的学习建议。
- 学习计划能结合用户目标和当前水平。

### 13.11 阶段 10：Agent 扩展

开发目标：将系统从被动问答扩展为主动学习辅助。

主要任务：

- 设计学习规划 Agent。
- 设计教学 Agent。
- 设计出题 Agent。
- 设计分析 Agent。
- 定义 Agent 执行边界。
- 保存 Agent 建议和执行记录。

完成标准：

- Agent 可以根据学习目标生成计划。
- Agent 可以根据学习记录调整建议。
- 高影响操作需要用户确认。
- Agent 输出结果可解释、可追踪。

## 14. MVP 开发顺序

推荐按以下顺序开发：

```text
1. 初始化 Spring Boot 项目
2. 配置 MySQL 和 MyBatis-Plus
3. 创建统一响应 Result
4. 创建全局异常处理
5. 创建用户表和实体
6. 实现注册接口
7. 实现登录接口和 JWT
8. 实现登录拦截和当前用户上下文
9. 实现学习档案模块
10. 实现会话和聊天记录模块
11. 封装 DeepSeek 调用服务
12. 实现 AI 聊天接口
13. 补充接口测试和文档同步
```

开发时应按小步提交思路推进，每完成一个模块就进行接口验证。

## 15. 测试计划

### 15.1 用户注册测试

| 场景 | 期望结果 |
|---|---|
| 用户名为空 | 返回参数错误 |
| 密码为空 | 返回参数错误 |
| 用户名重复 | 返回用户名已存在 |
| 正常注册 | 返回注册成功 |

### 15.2 用户登录测试

| 场景 | 期望结果 |
|---|---|
| 用户不存在 | 返回用户名或密码错误 |
| 密码错误 | 返回用户名或密码错误 |
| 用户被禁用 | 返回账号已禁用 |
| 登录成功 | 返回 Token 和用户信息 |

### 15.3 权限测试

| 场景 | 期望结果 |
|---|---|
| 未携带 Token 访问档案接口 | 返回 401 |
| Token 无效 | 返回 401 |
| Token 正确 | 正常访问当前用户数据 |
| 访问他人会话 | 返回无权限或资源不存在 |
