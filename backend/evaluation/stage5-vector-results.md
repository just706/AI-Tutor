# 阶段五首个向量与混合检索候选对照

日期：2026-10-30。结论：**当前候选不接入应用，保留生产词法检索。** 本地BGE可以补回部分改写，但当前余弦阈值和RRF融合会让无答案问题获得不含答案的片段。没有一个预设配置同时在开发题和新题上表现为有改善且无退化。此结论限于本模型、分片和配置，不代表所有语义检索方案均无效。

后续已完成[答案依据规则验证](stage5-evidence-results.md)：旧两项误召回可由有限规则拦截，但新增语义对照仍有9项错误，未改变本报告“不接入应用”的决定。

开发集混合0.6补回S04机会成本改写与S07已有键覆盖，两题改善且该集无退化。然而新题相同配置没有新增通过题，反而让H13、H14退化。阈值0.5在开发集补回五题但造成四题退化，在新题补回两题也造成两题退化；不能只报告增加的命中。阈值0.8的混合方案回到两组词法基线，没有新增通过题。

新题的两个关键反例：

- **H13：蓝桥编码的发明者是谁？** 最高相似度约0.653，召回`synthetic_ext:0`，原文只有“把样本编号映射为颜色”的定义，没有发明者。混合0.6仍返回该片段。
- **H14：总体方差在这份调查中的实际数值是多少？** 最高相似度约0.733，召回`math_ext:3`，原文只有总体方差定义，没有任何调查数据。连0.7阈值也不能排除它。

这些是检索准入退化，不是已观测到模型生成了错误回答；本轮没有生成回答。指标要求无答案题在检索层正确留空，候选没有满足该要求。相似度不能解释为答案置信度。

原S09“导数这个术语……”和新H07“总体方差→它衡量什么？”都被共用指代解析要求澄清。所有候选复用同一个结果，因此这些失败保持原样，不计为向量改进或退化。本轮未修改指代实现。

## 模型与实验约束

使用[BAAI/bge-small-zh-v1.5固定提交](https://huggingface.co/BAAI/bge-small-zh-v1.5/tree/7999e1d3359715c523056ef9478215996d62a620)，MIT许可。下载七个白名单文件共96,405,251字节，权重采用`safetensors`并核对上游LFS SHA256；不下载或执行远端Python代码。模型文件留在Git忽略的`backend/target/stage5-models/`，不随源代码提交。

[配置](stage5-vector-config.json)在首次编码前保存：查询添加模型卡建议的中文检索前缀，正文不加；CLS池化、512维L2归一化、最大512 token、CPU四线程、文档批量8。超出token上限直接失败，不隐式截断教材。推理强制本地文件、关闭联网解析和遥测；只用当前问题、材料及Java已解析的对象，不传预期、评分要求或证据标注。

向量模式按余弦分数排序，再使用预设阈值与topK；混合模式对生产词法短名单和向量短名单做等权RRF，常数60。词法列表沿用当前服务的子问题与比较处理；向量模式对完整解析后问题编码，因此这里比较的是两条实际候选流程，不声称隔离出了编码器的纯因果作用。混合模式也不代表重新实现完整BM25索引或独立重排器。

所有四个阈值都在首次运行前写入配置，后续没有按结果增加或调整阈值。[新题集](stage5-retrieval-holdout.json)是在看到开发结果后由同一编码助手编写、在首次新题运行前冻结；它没有参与四个阈值的设定，但不是独立研究人员标注、盲法验证或真实用户样本。两组题不合并估计实际错误率，原Java20题、真实上传和分片未覆盖。

## 时延、调用和验证

开发集当前词法中位数约0.38ms，新题约1.21ms；候选估计中位数分别约13.6ms和15.3–15.5ms。候选时间是Java预处理／词法预跑中位数、本地查询编码三次中位数及Node排序耗时之和；向量模式也包含词法预跑，以复用同一指代结果。它不是一次HTTP请求的实测端到端时间，不能直接用于生产SLA。模型加载约2.2–2.3秒、文档编码约0.21／0.42秒另行记录，真实长文索引成本未知。

开发集运行两次（首轮66、最终复跑66次前向计算），新题运行一次（44次），合计176次**本地编码前向计算**，包含预热及计时重复。**外部模型调用0次，教学回答生成0次**，没有使用已耗尽的DeepSeek预算；公开模型下载是网络传输，不是模型推理API调用。

新增7项候选测试、2项自定义题集验证都先观察失败，再实现；最终脚本全套97项通过。测试覆盖阈值边界、归一化／维度／NaN、候选范围、RRF顺序、保留澄清、结果缺失／重复和双向退化统计。Python语法检查通过，两套真实本地模型运行完成；模型71组权重全部加载，无缺失或随机初始化权重提示。应用Java、前端和数据库未修改，本轮未重跑应用构建或浏览器验收。

候选的SQL权限、用户所有权、删除／重处理后的失效、真实上传解析、线上索引、故障回退、回答及引用语义、教学效果均未验收。新题H12只证明在预过滤片段集合内执行检索，不能替代线上权限测试。下一候选优先验证“片段是否包含所问答案”的准入判断，再做检索融合；不会用提高相似度阈值作为已解决这些问题的证明。

## 复现

依赖：现有Java17后端构建与`backend/target/dependency`、Node，以及Python 3.11环境中的`torch 2.13.0+cpu`、`transformers 5.10.2`。后两项是本轮实际运行版本；Python只用于离线编码，不是在线服务或Agent。编码不要求`sentence-transformers`。

首次下载固定公开模型（需要网络；输出必须是新目录）：

```powershell
cd D:\AI-Tutor
python backend/scripts/prepare-stage5-model.py --output-dir backend/target/stage5-models/bge-small-zh-v1.5-7999e1d
```

本机已经下载时跳过上述命令。当前后端未构建或源码有更新时，先按[基线说明](stage5-retrieval-results.md#复现与验证)构建。使用新的输出目录运行：

```powershell
node --test backend/scripts/*.test.mjs
node backend/scripts/evaluate-stage5-vector.mjs --model-dir backend/target/stage5-models/bge-small-zh-v1.5-7999e1d --output-dir backend/target/stage5-vector-new-development
node backend/scripts/evaluate-stage5-vector.mjs --model-dir backend/target/stage5-models/bge-small-zh-v1.5-7999e1d --suite-file backend/evaluation/stage5-retrieval-holdout.json --output-dir backend/target/stage5-vector-new-holdout
```

可用`--python-bin`和`--java-bin`显式指定运行环境。每次都重新运行当前Java基线；默认24题检查原冻结题集和输入指纹，自定义题集先检查ID、候选范围及预期证据。每次编码产物绑定输入、配置、编码器和模型文件SHA256；所有算法、题集与脚本均保存快照。任何已有输出目录或编码文件都会拒绝覆盖。

候选比较脚本退出码0只表示至少一个配置在**本次题集**存在改善且无退化，仍标记`candidateAcceptance:not_accepted`；1表示没有这样的配置，2表示执行或输入失败。因此开发集返回0，新题返回1，两者都正常完成实验。不能把开发集退出0当作阶段五通过。词法基线子脚本的退出码仍遵循其原有“全部题通过／有失败／执行错误”语义。

原始运行保存于Git忽略目录：`backend/target/stage5-vector-comparison-a`、`stage5-vector-comparison-b`及`stage5-vector-holdout-a`。仓库内两个JSON分别逐字节复制最终开发复跑与新题的`report.json`；首轮开发记录继续保留。开发两次所有逐题命中和通过判决一致，计时不同；原始向量、各阈值完整结果和日志在对应目录中，可依配置重新生成。阶段五继续进行，阶段二、四的未验收项不变。
